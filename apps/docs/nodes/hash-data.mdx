**Node type:** `hash_data` · **Version:** `1` · **Category:** Data

Create a deterministic SHA-256 digest of JSON data. This node is not marked with the catalogue's generic side-effect flag. That classification is not a guarantee that every configured operation is read-only; review the concrete action and its destination.

## When to use this node

- Create a deterministic SHA-256 fingerprint for JSON-compatible data.
- Compare content without carrying the complete value into a later decision.

## Example: Fingerprint a normalized record

Hash one stable object after field mapping.

## Execution behavior

- Objects are canonicalized before hashing so property insertion order does not change the digest.
- The node returns a lowercase hexadecimal digest and the canonical byte count.
- The editor catalogue declares `hash` (string), `bytes` (number) for mapping. The execution inspector can contain additional evidence fields; inspect a real result before selecting nested paths from object or any outputs.

## Common issues

- Semantically different types produce different digests; string 1 and number 1 are not interchangeable.
- A hash is an integrity fingerprint, not encryption or secret storage.
